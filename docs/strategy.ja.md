# 必勝法

Nim は完全に解かれたゲームです．rs-nim はその解法を `game::winning_move` に実装しており，ヒント（`h`）と CPU の両方がこれを使います．

## 通常ルール: Bouton の定理

各山の個数を 2 進数で書き，すべての XOR を取ります．これが **ニム和** です．

- ニム和が **0** なら，手番側は相手が最善を尽くす限り負けます．
- ニム和が **0 でない** なら，手番側の勝ちです．ニム和を 0 にする手が必ず存在します．

その手は次のように求めます．ニム和を `s` とし，`h XOR s < h` となる山 `h` を選んで，`h XOR s` 個まで減らします．

山が `3 4 5` の例:

```text
  3 = 011
  4 = 100
  5 = 101
XOR = 010   -> ニム和 2．手番側の勝ち
```

`3 XOR 2 = 1 < 3` なので，山 A から 2 個取ります（3 → 1）．山は `1 4 5` になり，ニム和は 0 です．

ニム和パネル（`b`）は 1 が奇数個ある桁を強調します．すべての桁を偶数に戻す手が必勝手です．

古典的な `1 3 5 7` の配置はニム和が 0 なので，先手が必敗です．

## ミゼールルール

2 個以上の山が無くなる手を指す **直前まで** は，通常ルールと同じに指します．その時点で，1 個の山を（偶数個ではなく）**奇数個** 残します．こうすると相手は最後の 1 個を取らざるを得ません．

具体的には:

- 2 個以上の山が 2 つ以上ある間: 通常ルールの手を指す．
- 2 個以上の山がちょうど 1 つ: その山を 0 か 1 にして，1 個の山が奇数個残るようにする．
- すべての山が 0 か 1: 1 個の山が偶数個なら 1 つ取って勝ち．奇数個なら必敗．

## 検証

テスト `game::tests::strategy_matches_brute_force` は，3 つの山（各 0〜6 個）の全局面について，通常とミゼールの両方で，全探索（ミニマックス）と照合します．`winning_move` が手を返すのはちょうど勝ち局面のときであること，そしてその手を指した後の局面が相手にとって負けであることを確かめます．
